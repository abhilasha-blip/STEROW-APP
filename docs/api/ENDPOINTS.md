## Security

- **`apikey` header** (apiKey) — Supabase publishable key, required on **every** `SB` request (including before sign-in). Public/client-safe key (`sb_publishable_…`), value in openapi.json `info.description`; goes in `.env`, not source.
- **`Authorization: Bearer <access_token>`** (http bearer, JWT) — Supabase session access token. Global default = apikey + bearer.
- `APP` endpoints declare their own security: either none or Bearer only (no apikey).
- **Token lifetime:** "~1 hour" (`expires_in` in Session). **Refresh:** `POST SB/auth/v1/token?grant_type=refresh_token` with `{ refresh_token }` → new `Session`. Refresh-token lifetime / rotation is not documented (Supabase default: rotating, single-use).

## Error envelopes (two different formats!)

| Server | Success | Error | Verified live |
|---|---|---|---|
| `SB` (PostgREST/GoTrue) | raw JSON (row array / object / Session) | `{ code, message, details, hint }` (PostgREST). GoTrue auth errors use their own shape (typically `{ code, error_code, msg }`) — not documented in spec | No (doc only) |
| `APP` | `{ "data": … }` | `{ "error": { "code", "message" } }` | **Yes** — e.g. `400 {"error":{"code":"bad_request","message":"Enter a valid India or UAE mobile number"}}` |

Status meaning per spec: 401 = missing/expired token, 403 **or an empty list** = blocked by role permission (RLS).

### Session

| Field | Type | Required? |
|---|---|---|
| `access_token` | string | optional (spec lists no required fields) |

**That is the only named schema.** Every other request body is inline (shown in the table above) and every table/RPC response is an untyped `object`/`array<object>`. Typed responses will need Supabase-generated DB types (`supabase gen types typescript`) or confirmed examples from the backend — see API_PLAN.md open questions.

## PostgREST conventions (apply to every `/rest/v1/<table>` row)

- GET list: `?select=*,relation(col)&<col>=eq.<v>&order=created_at.desc&limit=20&offset=0`, header `Prefer: count=exact` → total in `Content-Range`.
- POST create: header `Prefer: return=representation` → `201` with array of created rows.
- PATCH update: required filter `?id=eq.<uuid>` + `Prefer: return=representation`.
- DELETE: `?id=eq.<uuid>` → `204`; **soft delete** (is_active=false, deleted_at set, children disabled; media files removed for real).
- RPC: `POST /rest/v1/rpc/<fn>` with JSON args (names prefixed `_`).
